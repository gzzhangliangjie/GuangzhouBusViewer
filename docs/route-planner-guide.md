# 路线规划功能全档（使用说明 · 流程 · 踩坑记录）

> 功能一句话：输入起点/终点 → **纯本地 A\*** 在「地铁 19 线 + 公交 1698 变体 + OSM 步行网快照」上算出门到门方案，按 **耗时 / 换乘** 双维度出 Top-3 方案并画在高德底图上。零 API 参与路线计算（地名→坐标是唯一例外，走兜底链）。
> 设计决策与参数口径：[route-planner-design.md](route-planner-design.md)。本文 = 使用说明 + 全流程档案 + 踩坑判例。
> 状态：2026-10-29 实施完成，verify-route 18 断言 + verify-roadnet 9 断言全绿。**未提交。**

## 一、使用说明

### 1.0 出行模式（五种，2026-10-29 用户令）

顶部模式条切换，各自独立导航逻辑：

| 模式 | 逻辑 | 输出 |
|---|---|---|
| 🚉 **公共交通**（默认） | 步行+公交+地铁联合 A*（本文档主体逻辑） | Top-3 方案，[耗时|换乘] 双维度排序 |
| 🚗 **驾车** | 路网快照有向图（oneway 生效）+ 类别速度（maxspeed 优先，缺省按类别 15~90km/h）× 常规路况系数 0.75 | 最快 / 最短 双方案 |
| 🚶 **步行** | 全程步行网真实路径（有界 Dijkstra，4.5km/h） | 单方案（距离+时长） |
| 🚌 **公交** | 换乘图车型过滤：只乘公交变体，换乘边限公交↔公交 | Top-3 |
| 🚇 **地铁** | 换乘图车型过滤：只乘地铁，换乘边限地铁↔地铁（站内 0 距离 + 4min 站内换乘罚） | Top-3 |

驾车/步行模式下接驳圈隐藏；驾车估时含常规路况系数（不含实时拥堵，底图注记已说明）。

### 1.0b 中途点（动态途经点）

「＋ 中途点」按钮插入途经行（最多 5 个），每行具备与起终点相同的联想/钉确认/地图点选能力；⇅ 交换 = 终点与起点互换 + 中途点倒序。
- 公交族模式：逐段规划连缀，**每段按同一排序口径独立选拔**（2026-11-03 用户令「优先时间那几段都优先时间，优先换乘那几段都优先换乘，本质就是当成几段单独计算」）：耗时优先→每段最快；换乘优先→每段最少换乘（同数取最快）。口径=界面「排序」按钮，偏好跨查询持久；**链只有 1 个方案时也渲染排序行，切换即整链重算**。行程中段显示「📍 中途点：X」分隔，摘要为各段合计（换乘数跨段累计）。
- 驾车/步行：逐段 Dijkstra 连缀（顺序途经天然全局最优，无换乘概念不受口径影响）。
- 最近查询历史按整条链（含中途点与模式）记录/回填。

### 1.1 入口与界面

顶部导航「**路线规划**」（公交路线之后第 2 位）。界面 = 左侧输入/行程栏 + 右侧高德底图。

```
┌──────────────┬────────────────────────────┐
│ ● 起点输入    │                            │
│ ⇅ 交换       │        地图                │
│ ● 终点输入    │  （起终点大头针+接驳圈     │
│ [查询路线]    │   行程按线色绘制           │
│ [📍起点][📍终点]  步行段虚线走真路）       │
│ 状态行        │                            │
│ 方案切换条    │                            │
│ 行程分段卡片  │                            │
└──────────────┴────────────────────────────┘
```

### 1.2 起终点输入（三通道互补）

| 通道 | 操作 | 适用 |
|---|---|---|
| **A 键字联想** | 输入即出下拉：站名即时命中（公交 6660 + 地铁 318 统一索引，括号后缀自动剥离），地名走高德 POI 兜底（400ms 降抖）。候选带线色徽标/所属线路/邻近地标；同名多实例（相距 >500m）分开列出 | 记得名字 |
| **B 地图钉确认** | 点选候选 → 地图飞行落大头针（起点绿/终点红）+ 2km 接驳圈，输入框变已选态（× 清除重选） | 防选错，零成本反悔 |
| **C 地图点选** | 「📍起点/终点」按钮进拾取模式，鼠标移动实时吸附 800m 内最近站（黄圈+名牌），点击落钉，Esc 取消 | 不知道站名 |

- 键盘：↑↓ 选候选、Enter 确认（终点框 Enter = 直接查询）、Esc 关下拉。
- 直接回车不选下拉时：精确站名 → 就近实例自动锚定；否则按地名解析（高德→Overpass 兜底）。
- **输站名也输地名**：公交/地铁站名走本地索引（离线秒出）；地名/小区/写字楼走高德 POI（结果本地缓存 7 天）。

### 1.3 方案池与排序

- 查询后出 **Top-3 方案**，按耗时排序， guaranteed 含一个换乘最少方案（哪怕它不是最快）。
- 方案条：`方案n · 约x分钟 · 换乘n`，换乘最少的方案带 **·换乘少** 徽标。
- **排序切换 [耗时|换乘]**：两个维度都可以作为主序看。
- 点击方案 chip 切换行程列表与地图绘制；点击行程分段卡 → 地图飞到该段。
- 摘要行：总耗时 / 换乘次数 / 步行距离（真实路网）/ 乘车距离。

### 1.4 计价口径（估时怎么来的）

| 项 | 口径 |
|---|---|
| 地铁 | 35 km/h 含停站均速，站序连线画图 |
| 公交 | 16 km/h，站间直线画图（v1） |
| 步行（首末段） | **OSM 步行网真实路径**（有界 Dijkstra），画真路折线 |
| 步行（换乘段） | 直线 ×1.4 绕行系数（短距误差可忽略） |
| 换乘罚 | **+4 分钟/次**（站内/跨站换乘含候车均值，2026-10-29 调升判例见 §5.1） |
| 首末接驳半径 | 站名/地名统一 2km，候选公交/地铁各留 4 席 |

### 1.5 离线与降级行为

- 路线计算**永不联网**：地铁/公交/步行网全部随包。
- `routing-graph.json` 缺失（如新克隆未拉路网）→ 首末步行自动退化为直线×1.4 估算，功能不瘫；跑 `electron test/pull-roadnet.js` 重建（约 2.5 小时，断点续拉）。
- 地名搜索：未配高德 key 也有内置默认 key（amap-line.js DEFAULT_KEY）；显式清空 key = 关闭高德通道，落 Overpass 按名查 POI（覆盖稀疏）。amap 配额打满时自动降级，站名输入不受任何影响。

### 1.6 其他

- **最近 5 条 OD**：localStorage（gzbus.route.recent.v1），输入框聚焦且为空时下拉顶部显示，点击整对回填。
- 起终点互换按钮 ⇅；地图右上角底图切换沿用公交视图。

## 二、架构与流程

### 2.1 文件清单

| 文件 | 职责 |
|---|---|
| `js/route-planner.js` | 引擎：站网图 + A* + Top-K + 站名索引 + 地名兜底（纯逻辑无 DOM） |
| `js/roadnet.js` | 路由图共享层：解码 + 步行 Dijkstra + 道路本地检索（RoutePlanner 与 RoadsView 共用） |
| `js/route-view.js` | 视图：输入/联想/钉确认/点选/行程渲染/Leaflet 绘制 |
| `data/routing-graph.json` | **路由图派生物**（~68MB）：路口压缩图 + CSR 邻接 + 边形状 + 类别/oneway/限速/路名 |
| `test/pull-roadnet.js` | 路网快照管线（分片拉取 + 构建期压缩），`ROADNET_MERGE_ONLY=1` 只合并 |
| `test/verify-route.js` / `test/verify-roadnet.js` | 验收门（25 + 9 断言） |
| `data/bus-lines-snapshot.json` / `data/metro-data.js` | 既有随包数据（只读消费） |

### 2.2 引擎查询全流程

```
输入解析 → 起终点候选（2km 内公交/地铁各≤4席，按类型分名额）
   ↓
首末步行边：RoadNet.walkPath 真实路径（Dijkstra）× 每候选
   + 虚拟终点 T（末端步行进 A* 代价 → 门到门）
   ↓
planK 三 profile：换乘罚倍率 [1, 3, 20] 各做 ≤3 轮惩罚边发散
   （罚上轮乘车边成对含孪生反向边；方案指纹去重）
   ↓
选拔：按总耗时排序，最快 k-1 个 + 保底「换乘最少」方案
   ↓
compress：边链 → 乘段（乘车按变体聚合 / 步行聚合）
   → {legs, summary} → 视图渲染 + 地图绘制
```

### 2.3 站网图构建（首次查询触发，进程内缓存，~350ms）

- 地铁：MetroData 19 线 318 站，节点键 = `线ref|站id`（**同线支线共享节点才连通**），环线闭合。
- 公交：bus-lines-snapshot 1698 变体，节点 = 站点实例（**不做同名合并**——跨线同站是独立实例，靠换乘边连接）。
- 换乘边：250m 空间邻近（网格 cell 300m，每站最多 8 条），成本 = 步行×1.4 + 4min 罚。
- 站名索引：归一化（剥括号后缀/空白）→ 前缀命中优先的联想。

### 2.4 步行网快照管线（Valhalla 式：压缩在构建期，App 只轻解码）

```
Overpass 8×8 分片拉取（断点续拉，assets/_pull-roadnet/ 原始片不入库）
  → 合并（⚠️按 way id 去重）：
     节点 = 交叉路口/端点（非路口形状点 ≥30m 抽稀进边形状，差分编码）
     CSR 双向槽位邻接；每边携带 类别枚举/oneway/maxspeed/路名id
  → data/routing-graph.json（~68MB）
  → App 端解码 ~300ms（类型化数组 + 计数排序网格 + 代际戳 Dijkstra 缓冲）
```

消费方：①路线规划首末步行（真实路径进 A\* 代价 + 行程画真路折线）；②道路查看本地检索（`searchRoads` 秒出/离线，Overpass 降为兜底，状态栏标注来源）；③驾车模式（未来：oneway 有向边 + 类别速度，基础数据已入边）。

### 2.5 地名 POI 兜底链（唯一 API 场景）

```
本地站名索引（精确命中即止，离线）
  → 高德 place/text（内置默认 key，可配置/可清空；kwLadder 尾缀剥降级逐词重试）
  → Overpass 按名查 POI（免 key 最后手段，正则并集+命中长度排序）
  → localStorage 缓存 7 天（gzbus.poi.v1.*）
```

### 2.6 道路查看改造

`roads.js searchRoads`：快照本地检索（`RoadNet.searchRoads`，同构返回）→ 空结果才走 Overpass 在线。状态栏标注「本地路网快照 / OSM 在线」。

## 三、踩坑记录（判例档案）

> 格式：现象 → 根因 → 修法。改引擎/管线前先过一遍本节。

### 5.1 计价模型

- **「6 换怎么可能 48 分钟」**：换乘罚 2min 时，地铁站内换乘（两线站坐标相同、步行 0m）几乎免费，多换公交方案被严重低估。→ 罚时调 4min（站内/跨站含候车均值），6 换方案如实涨到 60+ 自然出局。**规则：换乘代价必须显式进总时长，不许只当排序 tiebreaker。**
- **「聚仁坊到团一大广场没那么近」**：直线 161m、系数 1.4 估 225m，实走 **470m（2.92×）**——老城街巷绕行系数法根本兜不住。→ 首末步行上 OSM 路网 Dijkstra。**规则：步行距离要诚实，长距离步行宁可如实计入吓退方案，也不许低估美化。**

### 5.2 引擎（route-planner.js）

- **双向边反向站序**：addRide 成对边里反向边 ia>ib 递减，压段按升序 i0..i1 切片会切出空段。→ 压段按节点链（pos 数组）记录旅行顺序，不做升序假设。
- **地铁支线不连通**：支线若独立建节点，与主线无共享边。→ 节点键 = `线ref|站id` 同线共享。
- **支线边站序越界**：边携带的 ia/ib 是段内局部序，主线在前支线续接后错位。→ 建边时加主线基偏移 base。
- **NaN 乘车距离**：pathM 收到 leg.pts（`[lat,lng]` 数组）却按对象取 `.lat` → NaN → JSON.stringify 显 null。→ LL() 兼容两种形态。
- **虚拟起点**：首段步行边 from=-1，compress 取 nodes[-1] 崩。→ compress 接收 originPt，fromIdx<0 时用真实起点坐标。
- **起终点候选被挤占**：只取「最近 N 站」时老城密集公交站占满名额，地铁站进不了候选，低换乘地铁方案连参赛资格都没有（用户问"为什么不是 1号线+5号线"抓出）。→ 按类型分名额（公交/地铁各 4 席）。**规则：候选择优必须分类型保底，单一距离序会系统性偏科。**
- **少换乘 profile 永不运行**：`plans.length < k` 让最快 profile 先填满池子，后面 profile 直接跳过。→ 三 profile 全跑，最后统一选拔（最快 k-1 + 保底最少换乘）。
- **换乘罚太轻等于没有**：倍率 20 的字典序少换乘搜索，罚 2min 时长步行+1换的总代价永远输给短步行+2换。→ 罚时 4min + 倍率梯度到 20。
- **k=1 语义三改定稿（2026-11-03 用户判例「插入中山大学后指定地铁让我步行过去」）**：①数据显示层 GCJ 未纠偏（见 §5.6）加剧了接驳错位；②选拔层曾把 k=1 写成"必返最快"，0 换乘方案永远浮不上来。初版误修"保底最少换乘只用于 k≥2"，用户复令「保证每一段都是最少换乘」；再令定稿：**「优先时间那几段都优先时间，优先换乘那几段都优先换乘——本质就是当成几段单独计算」→ 终版链每段按同一排序口径独立选拔，口径=UI 排序按钮（planK 第 4 参 pref 'time'|'xfer'），偏好跨查询持久**；k≥2 两点查询恒为"最快 k-1 + 保底最少换乘"池不受影响。**规则：链段选拔口径必须与用户可见的排序偏好同源，不许另设默认；换乘是稀缺资源（点名 50min/1换 胜 41min/3换 判例），长步行如实展示由用户裁决。**
- **三 profile 罚空间必须独立（同日判例，池发现缺陷）**：曾共用一张 penalties Map 贯穿 9 轮 A*——mul=1 先摸过的乘车边带着罚时进入 mul=20（最少换乘偏置）搜索，把真正最快的 0 换乘方案压在池外：中山大学→广州塔 浮上来的是经鹭江 39min/步行2.73km 的 0 换乘，而经中大站 36min/步行2.36km 因所骑边带 +6min 罚（搜索代价 48>45）永不入池。→ 每个 xferMul profile 开独立 `penalties = new Map()`，profile 间只靠 sig 去重不共享罚。修后 k=1 稳定取 36min/0换。**规则：多 profile 搜索的偏置资源（罚/启发）不得跨 profile 泄漏，否则后面的 profile 是"戴着前人枷锁"的假搜索。**

### 5.3 路网快照管线（pull-roadnet.js / roadnet.js）

- **加载期压缩卡死**：200 万原始节点在 App 加载期建朴素邻接表（每节点一个 JS 数组）直接卡死渲染进程。→ **压缩必须构建期做**（Valhalla 式）：发布路口压缩图 + CSR + 类型化数组，App 只解码（300ms）。
- **跨分片路面重复输出**：一条路横跨多片在每片各输出一次，不去重则节点计数翻倍、全部节点被误判成交叉路口（实测 109 万"路口"）。→ 合并按 way id 去重。
- **⚠️TaskStop 僵尸进程覆盖分片**：Windows 下杀后台任务只杀了 bash 壳，Electron 子进程存活，按**旧 4×4 网格**继续往同目录写**同名**分片，把 8×8 正确拉好的中心城区片覆盖成从化数据——黄埔大道就这样消失的。→ ①同一目录只跑一个拉取进程；②分片校验器按「内容落在应有 bbox 的比例」清洗（<50% 删）；③重拉后全量重合并。
- **近邻网格行数算小**：网格按 lng 跨度 21.6km 假设给 258 行，广州东部（lng>113.29）路口整体越界丢失（诗悦网络一带 walkPath 全 null）。→ 行数按实际覆盖开足（512）。
- **回溯链方向反了**：`prevSlot[child]` 存的是**父邻接表**里指向 child 的槽位，`adjNbr[s]` 是 child 自己——回溯 `cur = adjNbr[s]` 永远走回自己，自环疯转到数组爆长（RangeError 判例）。→ 另存 `prevNode[child] = 父路口`，回溯走 prevNode。**规则：边上的 slot 只够还原形状方向，拓扑回溯必须显式存父节点。**
- **单片过大超时**：4×4 分片单片原始响应 40MB+ 级，镜像集体超时。→ 8×8 细分（5-25MB/片），断点续拉。

### 5.4 视图与测试方法论

- **preferCanvas 断言**：Leaflet preferCanvas 模式下线路画在 canvas 上，`.leaflet-overlay-pane path` 恒为 0。→ 程序化断言 = 数 canvas 非透明像素采样（getImageData 步进扫 alpha）。
- **willReadFrequently 噪音**：测试自身 getImageData 采样会触发 Chromium 性能提示进控制台报错收集。→ 报错收集过滤该词。
- **高德配额/网络依赖**：验收脚本里的 POI 探针若依赖 findPoi，amap 配额满会静默落 Overpass 慢速竞速拖死验收。→ 验收用**硬编码历史实测坐标**，或确保注入 key 且预算重试；**规则：验收必须确定性，外部 API 只测"通道存在"，不测具体数据。**
- **script 版本参数**：`?v=` 不递增时 Electron 会用旧缓存 roadnet.js（改了文件没改参数 = 白改）。→ 每次改这三个文件 v 参数同步递增。
- **vm 沙箱跑引擎**：顶层 `const` 不挂 context 对象，取引用要 `vm.runInContext('RoutePlanner', ctx)`；ctx.fetch 桩会劫持高德请求，按 URL 分流。
- **测试 profile 的 localStorage 跨轮持久**：注入的 key/POI 缓存会污染下一轮断言，隔离 userData（mkdtemp）或预清键。

### 5.5 五模式扩展（第二批判例）

- **drivePath 全 null**：起点吸附到的最近路口常是**站前 footway 节点**（无机动车边可达），Dijkstra 从它出发寸步难行。→ 装载时一遍槽位扫描标记 `jDrive[路口]`（有可驾车入边），驾车吸附按需过滤（半径放宽到 1200m）。**规则：多模式共用一张图时，"就近接入"必须按模式的可通行类别过滤吸附点。**
- **oneway 方向语义**：槽位 `adjRev=0` = 路面正方向（a→b）；`oneway=1` 禁 rev=1 槽、`oneway=-1` 禁 rev=0 槽。
- **驾车估时偏乐观**：自由流车速（高速 90/主干道 50…）比现实快 30% 左右。→ 常规路况系数 ×0.75（不含实时拥堵，UI 注记声明）。
- **纯步行 UI 崩溃 `reading 'length'`**：sumLegs 把途经点伪腿（无 pts）喂进 pathM。→ sumLegs 跳过 wp 腿。
- **站内换乘卡消失**：重写渲染时把「首末位 <30m 贴站步行隐藏」误写成「凡无 keep 标记即隐藏」，中段站内换乘 0m 卡被吞。→ 恢复按位置判断（首末位才隐藏）。**规则：渲染过滤条件改动必须带齐原维度（位置/距离/标记），不能只换一个判据。**
- **旧格式历史记录崩溃**：历史条目结构升级（from/to → fixes 数组）后，旧记录进入联想展示即 `reading 'map'` 崩溃。→ loadHistory 过滤无 fixes 的旧条目。**规则：localStorage 结构升级必须兼容或显式丢弃旧格式。**

### 5.6 坐标系与纠偏（第三批判例，2026-11-03）

- **「中大站定位点在珠江里」= window.GCJ 未挂载，纠偏从未执行**：`js/coords.js` 顶层 `const GCJ = ...` **不创建 window 属性**，而 roads.js / route-view.js / route-planner.js(gcjToWgs) 三处守卫全写成 `window.GCJ ? GCJ.wgs84ToGcj02(...) : 原值`——恒假 → WGS 数据在 AMap(GCJ) 瓦片上**整体西偏约 550m**，中大站节点恰好落进后航道；POI/地图点选的 GCJ 坐标也不反算 WGS，起终点接入系统性错位。公交线查看器因 map-layer.js 用**裸 GCJ 引用**一直正常，恰好掩盖了问题。→ coords.js 末尾 `window.GCJ = GCJ;` 一行全修。**规则：坐标纠偏守卫统一用裸 `GCJ`（脚本序已保证 coords.js 先行加载），禁止 `window.GCJ` 存在性判断——const 声明不挂 window。**
- **坐标口径（全链对质结论）**：地铁 metro-data.js = OSM(WGS) 忠实拷贝、公交快照 = Overpass/OSM(WGS)、路网快照 = Overpass(WGS)——**图内一律 WGS**；仅两类输入是 GCJ：高德 POI fix（`wgs:false`，入图前 gcjToWgs）与地图点选（瓦片坐标即 GCJ，同样先反算）。显示出口统一 `project(lat,lng,wgs)` 转 GCJ。
- **「数据错了」先做双源对质再动手**：中大站坐标疑案用 Overpass（OSM 声明源）+ AMap POI（findPoi GCJ→WGS 换算）双源对质——中大/晓港/客村/广州塔/中大南门/滨江东路全部 ≤42m 吻合，**数据无罪**，是显示未纠偏。⚠️手算 GCJ 偏移极易错（实测该处偏移 ≈(+0.0027, −0.0054)，方向记反就多出 500m 假案）——换算一律走 coords.js 代码，禁止心算。**规则：坐标疑案先换算对质两源，误差 <50m 即判显示层问题，不动数据。**
