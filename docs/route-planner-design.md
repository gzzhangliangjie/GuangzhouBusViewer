# 路线规划功能设计文档（公交+地铁联合出行）

状态：已实施（2026-10-29）。验收 = `test/verify-route.js`（18 断言）+ `test/verify-roadnet.js`（9 断言），全绿。
使用说明/全流程/踩坑判例档案：[route-planner-guide.md](route-planner-guide.md)（本文只留决策与参数口径）。
关联记忆：路线查询 = 输入起点/终点 → 本地图搜索 → 地图绘制通行路线。

## 0. 结论先行：自己算，不调 API

**纯本地计算完全可行**，所需数据全部已在包内，无需任何联网调用：

| 数据 | 来源 | 规模 | 质量 |
|---|---|---|---|
| 地铁线网 | `data/metro-data.js`（MetroData 已在内存） | 19 线 · 318 站，站序+经纬度+线色 | 完整，直接成图 |
| 公交线网 | `data/bus-lines-snapshot.json`（随包，22.7MB） | 1768 变体 · 3.4 万站次 · 6660 站名，站序+经纬度 | 站级图够用 |

- 公交快照本就是 App 离线兜底数据源（`Overpass.loadLinesSnapshot`），路线规划直接消费同一份，**零新数据链、零新管线、不改现有生成器**。
- API 的增量价值只有两块：**地名/POI 起终点识别**（2026-10-29 用户点名纳入，见 §1.2 D——包内无 POI 库，本地算不了，按"不行才调 API"走兜底链）与实时到站/班次（本次不做）。核心路线计算始终纯本地。
- 与"启动零联网"用户令天然一致：整个功能离线工作。

## 1. 核心算法：换乘图 + A* 最短路

### 1.1 图构建（首次查询时构建，进程内缓存）

```
节点 = 站点实例（不做同名合并，同名异位站天然是两个节点）
边   = 乘车边（同一线路变体上相邻两站，双向）
     + 换乘边（空间邻近的任意两站，步行）
```

- **乘车边**：地铁 = `MetroData` 每条线 stations 相邻站对（环线首尾相接、支线同样入图）；公交 = 每个变体 stops 相邻站对。边权 = 距离/速度（见 §2 参数表）。
- **换乘边**：网格空间索引（cell ≈ 300m），每站只与半径 250m 内的站连边（同站不同名、马路对面站台、地铁口↔公交站全靠它，**不依赖站名匹配**，同名异位不会误接）。每站最多保留 8 条最近换乘边防爆。
- **规模**：约 3.5 万节点 / 7 万边，浏览器内构建 + 搜索均在百毫秒级。

### 1.2 起终点搜索确认（交互细化，2026-10-29 用户点名要做）

三个输入通道互补，覆盖"记得站名"和"不记得站名"两类场景：

**A. 键字联想下拉（主通道）**

- 站名统一索引：公交 6660 + 地铁 318 归一化合并（全角/括号后缀剥离，如「体育西路（地铁站）」→「体育西路」），前缀命中排前、包含命中排后；内存索引输入即查，60ms debounce。
- 候选条目三段信息：**站名 + 类型徽标（地铁线号色块 / 公交蓝点） + 归属线路前 3 条**。
- **同名多实例在下拉里直接分开列出**（相距 >500m 的才算不同实例），每条附「邻近地标」= 距它最近的 2 个其他站名（如「体育中心 · 邻近 天河路/体育东路」），这是同名消歧的主要手段。
- 键盘：↑↓ 选、Enter 确认、Esc 关下拉；终点框 Enter = 直接查询。

**B. 选中后地图钉确认（防选错）**

- 点选候选 → 地图飞行到该站 + 落大头针（起点绿/终点红）+ 800m 接驳圈；输入框原位变成已选 chip（线色点 + 站名，点 × 清除重选）。
- 用户肉眼核对位置，选错（同名异位/近似站名）点 × 重选即可，零成本反悔。
- 两端都钉上后「查询路线」按钮才点亮。

**C. 地图点选（不记得站名时）**

- 地图右上角两个大头针小按钮「选起点 / 选终点」→ 地图进拾取模式（十字光标），**鼠标移动实时吸附高亮 800m 内最近站** + tooltip 显示站名，点击落钉，Esc 取消。
- 解决"知道那栋楼/那个路口，不知道公交站叫什么"的场景。

**D. 地名/地标兜底（本地无数据的唯一 API 场景）**

包内只有站点数据，没有全城 POI 库（小区/写字楼/景区/道路名）——地名识别是"自己算不了"的场景，按用户原则走 API 兜底，且只做兜底层：

- **三级候选链**：① 本地站名索引（秒出、离线、主路径）→ ② 高德 place/text POI 搜索（复用"高德补源"的已存 key 与 roads.js `locateByAmap` 先例，返回 GCJ-02 与底图同系；结果按名称 localStorage 缓存免重复调）→ ③ Overpass 按名查 POI（无 key 时的免 key 兜底，复用镜像竞速；OSM 国内 POI 覆盖稀疏、更慢，仅作最后手段）。
- **候选条目带类型徽标**：地铁站（线色块）/ 公交站（蓝点）/ 地标（灰楼图标 + 所属区），下拉里混排——站名命中排前、地标在后。
- **地标锚定（门到门，2026-10-29 实测补强）**：地标得一个经纬度点后，两端都以虚拟起/终点接入路网——起点侧虚拟源向半径内候选站连步行边；终点侧向候选站连**合成末端步行边进 A\* 代价**（防止"只寻优到半径内任一站点、终在离目的地很远的站"），行程两端自动补步行段画虚线；站名作端点时末端≈0m 由视图 <30m 过滤规则隐藏。半径：站名输入 300m（顺脚换邻近站）/ 地名输入 2000m，行程首末段显示"从 XX广场 步行 650m 至 体育西路站"。
- **优雅降级**：无 key 且 Overpass 不通时，地名输入查不到就明确提示"未找到该地名，可尝试附近公交站/地铁站名"，站名输入全流程照常离线可用。

**辅助**

- 起终点互换按钮（⇅）。
- 最近查询：localStorage 存最近 5 条 OD 对，输入框聚焦且为空时下拉顶部显示，点击整对回填。
- 自动锚定兜底：若用户直接回车不选下拉，取"离对方端点候选重心最近"的实例（两端都这样定）。
- 起点/终点各自向 800m 内最近 ≤6 站连步行边（首末段步行），地图上画虚线。

### 1.3 搜索

- **A\***，启发式 = 两点直线距离 ÷ 全网最高速度（35km/h，地铁），可采纳必最优。
- 权重全部折算成分钟（参数见 §2），换乘代价天然由"步行边时间"承担，另加固定换乘罚时防止频繁换乘。

## 2. 时间参数（集中在文件头常量区，可调）

| 参数 | 取值 | 说明 |
|---|---|---|
| 地铁速度 | 35 km/h | 含停站均速 |
| 公交速度 | 16 km/h | 含停站均速 |
| 步行速度 | 4.5 km/h | |
| 每次换乘罚时 | +4 min | 2026-10-29 用户判例"6换怎么可能48分钟"后由 2 调升：站内 0 距离换乘几乎免费严重失真；4min=站内/跨站换乘含候车均值，叠加真实步行时间 |
| 换乘边半径 | 250 m | 空间索引 cell 300m |
| 首末步行接入半径 | 300m(站名) / 2000m(地名) | 按输入类型区分 |
| 接入候选站数 | ≤8，公交/地铁各≤4 | 按类型分名额（2026-10-29"为什么不是1号线+5号线"判例：只取最近N站时老城公交站挤满名额，地铁站永远进不了候选，低换乘地铁方案连参赛资格都没有） |

## 3. 结果后处理与展示

- 路径边序列压缩成**乘段**：同变体连续乘车边合并为一段（线路号/颜色/方向/上车站→下车站/乘坐站数/估时），步行段单独成段（距离+估时）。
- 摘要行：总时长、换乘次数、步行总距离、乘车总距离。
- **多方案 Top-K（2026-10-29 用户令"加时间计算做最优路线排序"；同日追令"减少换乘和耗时是两个排序重要因素都要看"）**：`planK(from,to,k=3)` 双目标入池——换乘罚倍率 1（纯最快）与 3（向少换乘倾斜）各跑惩罚边发散（成对罚孪生反向边，不重复标准罚/重复加倍），按方案指纹去重合并，**按总耗时排序**且**保证换乘最少的方案必在池内**；UI 方案条带 排序[耗时|换乘] 切换与"·换乘少"徽标，点击切换行程与地图。门到门末端步行已含在每个方案的代价里。实测（聚仁坊→诗悦网络）：接入地铁候选后最优从 33min/3换（公交接驳）翻新为 26min/2换全地铁（6号+10号+5号）。
- 分段卡片：线色条 + 徽标式线路号（地铁用 MetroData 线色，公交用变体 colour 或调色板）+ 乘坐说明（"体育西路 上 → 公园前 下 · 8 站 · 约 18 分钟"）。点击分段地图飞到该段。

## 4. 地图绘制（复用既有模式）

- 新建独立 Leaflet 实例（`#route-map`），完全照 roads.js 成熟套路：`ResizeObserver` 挂容器防 0×0 灰底、高德底图 + `GCJ.wgs84ToGcj02` 纠偏、取景 fitBounds 留边。
- 线型：地铁段用 `MetroData.geoSegments` 真实折线；公交段 v1 用站间直线连线（圆角衔接，视觉可接受；后续可选从变体 segments 切片取真实路形）。
- 首末步行段 = 虚线；起点/终点大头针标记；换乘站空心圆圈。
- 沿途各乘段按线色着色 + 深色描边（同公交视图画法）。

## 5. UI 与接线

- 导航加 `data-mode="route"` 按钮「路线规划」，排第 4 位（公交/地铁/道路/线路之后）。
- `#route-view` 布局复用 roads-layout 侧栏+地图结构：侧栏 = 起点/终点输入（各带建议下拉）+ 交换按钮 + 查询按钮 + 状态行 + 行程分段列表；右侧地图。
- `metro-quiz.js showMode()` 加 route 分支 → `RouteView.show()`（首次进入才建图，状态行提示"首次构建路线网络…约 1 秒"）。

## 8. 步行网快照 + 道路网快照（2026-10-29 用户令"走步行网快照路线"，Valhalla 式构建期压缩）

**架构**：原始 OSM 只做构建期输入，发布紧凑派生路由图 `data/routing-graph.json`（~68MB），App 端只做轻解码（~300ms）——压缩在构建期做，不在加载期（教训：加载期构建 200 万节点朴素邻接表会卡死渲染进程）。

- **数据管线** `test/pull-roadnet.js`：Electron 网络栈，8×8 分片（0.2°级）断点续拉 Overpass `way["highway"]` 全类别（含无名小径）；合并产出：**交叉路口压缩图**（非路口形状点按 ≥30m 抽稀进边形状，差分编码）+ CSR 双向槽位邻接 + 每边 类别枚举/oneway/maxspeed/路名id。raw tiles 存 `assets/_pull-roadnet/`（git 忽略，可重建）。
- **管线三坑（都踩过）**：①跨分片路面重复输出，不去重则节点计数翻倍、全图误判路口（109 万"路口"判例）——按 way id 去重；②第一个 4×4 拉取进程 TaskStop 只杀了 bash 壳，Electron 僵尸存活继续按 4×4 网格覆盖写同目录同名的 8×8 分片，中心城区片被换成从化数据（黄埔大道消失判例）——分片校验器按"内容落 bbox 命中率"清洗；③网格行数按 lng 21.6km 假设算小，广州东部（lng>113.29）路口整体越界丢失。
- **回溯链方向坑**：`prevSlot[child]` 存的是**父邻接表**里指向 child 的槽位，`adjNbr[s]` 是 child 自己——回溯必须走另存的 `prevNode`，走 adjNbr 即自环疯转（RangeError 判例）。
- **共享层** `js/roadnet.js`：类型化数组解码 + 计数排序网格近邻 + 有界 Dijkstra（代际戳复用缓冲）。消费方：①`RoutePlanner` 首末步行段真实路径（距离进 A* 代价 + 行程画真路折线）；②`RoadsView.searchRoads` 本地检索秒出/离线（Overpass 降为兜底）。换乘段步行维持直线×1.4（短距误差可忽略）。
- **实测**：聚仁坊→团一大广场 实走 470m = 直线 161m 的 2.92×（用户"没那么近"经验证实，系数法 1.4 远不够——这就是弃系数上路网的原因）；聚仁坊→农讲所 1293m；黄埔大道西/中/东/隧道/辅路全家桶本地检索 55ms。
- 驾车模式（用户已确认方向）：同一张图按 oneway（有向边）+ 类别速度（maxspeed 已入边）换过滤与边权，方案池/排序/门到门全复用，另行立项实施。
